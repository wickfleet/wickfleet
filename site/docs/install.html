Install with Docker Compose

The quick start runs the whole stack on one machine, bound to 127.0.0.1: built-in login, a dry-run demo bot and a local git registry.

Needs

  • Docker with Compose v2, git and make
  • macOS or Linux. On Linux the stack runs as uid 1000, freqtrade's own user
  • Network access to pull images and, for replays, candles from the exchange

Start it

git clone https://github.com/wickfleet/wickfleet.git
cd wickfleet
make quickstart
StepWhat happens
Registryexamples/registry is copied to deploy/compose/data/registry and made a git repo. Bots and strategies saved in the UI become commits there
StackTraefik, the hub with built-in login, the UI, the docker guard and two socket proxies start from deploy/compose/compose.yml
Demo botthe hub starts demo, a dry-run bot on the EmaCross example (BTC, ETH, SOL on Binance), within about 30 s
First adminthe script prints a one-time setup token, valid for 1 hour. Open http://localhost:8000/hub/login, enter it and create the user admin, who owns the demo bot

Then open http://localhost:8000/ for the fleet. make quickstart-down stops the stack and the bots. Data stays in deploy/compose/data.

Settings

VariableDefaultMeaning
WICKFLEET_PORT8000local port
WICKFLEET_ROOTdeploy/compose/dataregistry, bot data, candles and state
WICKFLEET_HUB_IMAGEghcr.io/wickfleet/wickfleet-hub:latestthe quick start builds the hub from your checkout under this name
WICKFLEET_UI_IMAGEghcr.io/wickfleet/wickfleet-ui:latestpin a release such as :0.2.0
WICKFLEET_FREQTRADE_IMAGEfreqtradeorg/freqtrade:2026.10, pinned by digestthe only image a bot may run

Upgrade

git pull
docker pull ghcr.io/wickfleet/wickfleet-ui:latest
make quickstart

Data in deploy/compose/data is kept. Release notes list any new setting.

Where to run it

SetupAdvice
Defaultkeep it private: on your own machine, or on a server you reach over a VPN such as Tailscale, NetBird or WireGuard. The quick start binds to 127.0.0.1 for this reason
Publiconly behind your own reverse proxy with TLS and single sign-on, in WICKFLEET_AUTH=proxy mode with oauth2-proxy in front. Do not put the built-in login straight on the internet
Keysbot API keys and exchange keys stay on the host that runs the bots. The hub adds a bot's key per request, the browser never holds one

After the quick start

  • More users: wickfleet-hub user add <name> <viewer|operator|admin> in the hub container, password on stdin. See Roles and login
  • Your own bots: add them in the Bots page, or as files in the registry and commit
  • Behind a real domain: the same compose file with your proxy and TLS in front. For single sign-on use WICKFLEET_AUTH=proxy with oauth2-proxy

Every bot is a dry run on a simulated wallet. Live trading needs WICKFLEET_LIVE_TRADING=true on the instance, dry_run: false on the bot, a passing replay of exactly those settings from the last 7 days, and exchange keys from files on the host. The README has the details.
