Run multiple Freqtrade bots on one server

A Freqtrade bot runs one strategy. To trade several strategies, pair lists or exchanges at once, you run several bots next to each other. This page covers what each bot needs of its own, how that looks by hand, and how Wickfleet takes the bookkeeping over.

What every bot needs of its own

PartWhy it cannot be shared
Processone freqtrade trade process or container per bot
Configstrategy, pairs, stake and bot_name differ per bot
Trade databaseset with --db-url. Two bots must never write to the same database
API port and logineach bot serves its own REST API, so each needs its own port and has its own login
Exchange accountFreqtrade assumes it owns the account. Use one subaccount per bot where the exchange has them. On a shared account give each bot its own available_capital, and do not use tradable_balance_ratio

By hand with Docker Compose

One service per bot, each with its own user_data folder, database and host port:

services:
  trend:
    image: freqtradeorg/freqtrade:stable
    restart: unless-stopped
    volumes:
      - ./trend/user_data:/freqtrade/user_data
    ports:
      - "127.0.0.1:8081:8080"
    command: trade --config /freqtrade/user_data/config.json --db-url sqlite:////freqtrade/user_data/tradesv3.sqlite --strategy Trend
  meanrev:
    image: freqtradeorg/freqtrade:stable
    restart: unless-stopped
    volumes:
      - ./meanrev/user_data:/freqtrade/user_data
    ports:
      - "127.0.0.1:8082:8080"
    command: trade --config /freqtrade/user_data/config.json --db-url sqlite:////freqtrade/user_data/tradesv3.sqlite --strategy MeanRev

Each config.json needs the api_server section with enabled: true and listen_ip_address: "0.0.0.0", or the published port reaches nothing. The strategy file goes in that bot's user_data/strategies.

That is fine for two bots. Every further bot adds a service, a port, a password and one more login in FreqUI, where the bot list lives in the browser you typed it into.

From a registry with Wickfleet

In Wickfleet a bot is one small file in a git repository. The hub reads that registry every 30 seconds and creates, replaces or removes the bot containers to match.

name: trend
owner: alice
strategy: EmaCross
strategy_file: EmaCross.py
exchange: binance
pairs: [BTC/USDT, ETH/USDT]
stake_currency: USDT
wallet: 1000
max_open_trades: 3
dry_run: true
PartBy handWickfleet
New botnew compose service, config, port, passwordone file, saved in the UI or committed to the registry
Portsone published port per botnone. Every bot sits behind one origin at /bots/<name>/
API passwordsone per bot, typed into each browsermade by the hub per bot and added per request. The browser never holds the password, only a session token the bot issues
Historywhatever you keep yourselfevery bot and strategy change is a git commit
Containeryour compose defaultsall capabilities dropped, fixed binds, only images you listed
Real moneywhatever the config saysdry run unless the instance and the bot both switch it on and the host holds the bot's exchange key file. A save through the hub also needs a recent replay that passed

Try it

git clone https://github.com/wickfleet/wickfleet.git
cd wickfleet
make quickstart

Needs Docker with Compose v2, git and make, on macOS or Linux. Everything runs on one machine, bound to 127.0.0.1, and a dry-run demo bot is waiting in the fleet. More in the install guide, or look first at the read-only demo.
