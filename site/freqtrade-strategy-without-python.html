Build a Freqtrade strategy without Python

Freqtrade strategies are Python classes. Wickfleet lets you describe one as a small spec instead, built from blocks in the browser. The hub checks it, reads it back in plain words and generates the Python that Freqtrade runs.

What a spec can say

PartChoices
Marketspot, long only, one timeframe
Indicatorssma, ema, tema, highest, lowest, rsi, atr, adx, bollinger, macd, stoch
Conditions> < >= <= == crosses_above crosses_below rising falling
Combiningone level of all or any, for entry and for exit
Exitsstoploss, time-based ROI and trailing stop

An example

The demo bot of the quick start runs this spec:

{
  "version": 1,
  "name": "EmaCross",
  "description": "Demo: long when EMA 12 crosses above EMA 26 while price is above SMA 200, out when EMA 12 crosses back below.",
  "timeframe": "1d",
  "stoploss": -0.15,
  "indicators": [
    {
      "id": "ema12",
      "kind": "ema",
      "source": "close",
      "period": 12
    },
    {
      "id": "ema26",
      "kind": "ema",
      "source": "close",
      "period": 26
    },
    {
      "id": "sma200",
      "kind": "sma",
      "source": "close",
      "period": 200
    }
  ],
  "entry": {
    "all": [
      {
        "left": "ema12",
        "op": "crosses_above",
        "right": "ema26"
      },
      {
        "left": "close",
        "op": ">",
        "right": "sma200"
      }
    ]
  },
  "exit": {
    "any": [
      {
        "left": "ema12",
        "op": "crosses_below",
        "right": "ema26"
      }
    ]
  }
}

The readback the hub gives for it:

  • EmaCross trades 1d candles, long only
  • Buy when the 12-candle exponential average of the close crosses above the 26-candle exponential average of the close and the close is above the 200-candle average of the close
  • Sell when the 12-candle exponential average of the close crosses below the 26-candle exponential average of the close, or when the loss reaches 15%
  • It needs 200 candles of history before the first signal

Why a spec and not a text box

  • No typed text becomes code. Every name is checked against a strict pattern, the generator formats every number, and the description lands only in a comment, limited to plain characters on one line
  • make equivalence backtests the demo specs against hand-written twins and fails unless both make the same trades
  • A spec is a file in the git registry, so every change is a commit with an author
  • A hand-written .py strategy in the registry still runs as is. Review it like any code you run

From a sentence, if you want

Drafting a spec from a sentence is optional and needs an Ollama endpoint or an Anthropic API key you configure. The model only proposes the JSON. The hub validates it against the same whitelist and never saves a draft by itself.

What it cannot do

No shorts, no futures, no second timeframe and no indicator outside the list. For those, write the strategy in Python and put the file in the registry. Either way the bot can be replayed with bias checks before it starts.

Try it

git clone https://github.com/wickfleet/wickfleet.git
cd wickfleet
make quickstart

Needs Docker with Compose v2, git and make, on macOS or Linux. Everything runs on one machine, bound to 127.0.0.1, and a dry-run demo bot is waiting in the fleet. More in the install guide, or look first at the read-only demo.

Wickfleet is software for running trading bots, not a recommendation to buy or sell anything. Backtests and replays describe the past, not the future. Every bot is a dry run on a simulated wallet by default.
